# 评测：怎么造你自己的尺子

## 为什么不能用通用指标

检索系统的公开指标（召回率、MRR、nDCG）测的是「给定文档集和标准答案，排序对不对」。但记忆系统要回答的是：

- 三个月前提过的那件事，它还记不记得？
- 它记得的版本是不是被后来的事改写了？
- 问到一件根本没发生的事，它会不会编？

这三件事没有公开数据集，因为答案只在**你自己的**账本里。所以这套系统的评测只有一个办法：**从自己的日子出题**。

## 原则

1. **题目从正本来，不从想象来**。每道题必须能在正本里找到原文答案。
2. **不编题**。出题时如果找不到确切原文，这题作废，不凑数。
3. **答案唯一**。如果一个问法有两种合理解释，改问法，不改答案。
4. **题目保密**。公开「怎么造尺子」，不公开尺子本身——题目泄了，改代码的人会不自觉地对着题调参，尺子就废了。

## 题型

| 类型 | 考什么 | 例子（答案在正本某处） |
| --- | --- | --- |
| 召回 | 单点记忆还在不在 | 「上次讨论部署方案是什么时候？」 |
| 时间线 | 先后顺序对不对 | 「修空指针和改提交日志，哪个在前？」 |
| 温度 | 情绪权重有没有生效 | 「我最近一次因为什么事烦？」 |
| 跨本子 | 同一件事在不同本子里能不能对上 | 「规则里写的提交格式，我在账本里实际做到了吗？」 |
| 变笨检测 | 没发生过的事会不会编 | 「我上次去冰岛是哪天？」（正确答案：没有这回事） |

最后一类最重要。只测「记不记得」的系统，会奖励「什么都能答」的模型。

## 评分口径

每题四档，按记忆是否正确给分：

- **命中（1.0）**：答案要素齐、出处对。
- **部分（0.5）**：要素缺一半，或出处指错行但内容对。
- **漏（0）**：答「不记得」但正本里其实有。
- **错（−1.0）**：内容与正本矛盾，或答了不存在的事。

总分用平均分，不用加权。加权会让「变笨检测」被稀释——而那是最该盯的一项。

评测时**不看模型解释**，只看答案和出处。解释好看但答案错的，记错。

## 造题流程

每周一次，十分钟：

1. 从上周账本里挑三件「以后大概率还会被问起」的事。
2. 每件事写一题，写出标准答案和出处行号。
3. 从上周没发生的事里挑一件（同事、天气、别的项目都行），写一道变笨检测。
4. 存进自己的题库（不进本仓库），记上日期。

改引擎之后重跑同一套题，对比分数。分数掉了先查是不是题目本身过时了（正本改了行号），再查代码。

## 示例（用仓库里的 demo 语料）

demo 的正本是 `demo/corpus/日记.md`，虚构人物小林。三道假题：

1. 「小林 11 月 6 日修了什么 bug？」→ 空指针（边界条件写反），出处日记.md#L8。
2. 「面试被问的第一道题是什么？」→ 二分边界，出处日记.md#L12。
3. 「小林上周去冰岛了吗？」→ 没有这回事（变笨检测）。

这三题可以直接拿来验证引擎没坏，但它们太浅，只能当冒烟用，不能当评测集。

## 失败案例目录

调这套系统时踩过的典型问题，出题和排查时对照：

- **两字词召不回**：trigram 需要三个字符，短词落到 LIKE 才命中；如果查询词是「累」「烦」这种，要看短词分支是否正常。
- **近义表没覆盖**：用户换了个说法，字面不重合，近义表里也没有 → 漏。修法：把说法补进 `alias_file`，不要改检索算法。
- **冷记忆被过滤**：答案在 60 天前的卡里，热检索为空后冷捞才有 → 如果连冷捞都没出来，查 `cold` 阈值和卡的 `w`。
- **锚点错位**：〔原话〕指到相邻段落。多半是账本里同一天有多个小标题，锚点正则匹配到了错的那个。
- **同一天多件事混在一起**：卡片 `text` 写太宽，导入时一个段落盖住了好几件事。拆卡。
- **权重集体跳水**：某类记忆突然全冷 → 先看 `decay.kind` 是不是配错了类型名，再看日期解析是不是读到了错误的年份。
- **变笨**：问到不存在的事，模型顺着话头编。检查上下文里是不是放了「暂无相关记忆」这类占位——它会读成「有相关记忆但内容为空」。

## 不公开什么

- 65 道真题和答案：它们来自真实生活，含个人信息。
- 每道题对应的账本片段。
- 评测历史（哪次改了什么、分数怎么变）——能反推出题目。

公开的是：题型分类、评分口径、出题流程、失败案例的**模式**（去掉具体内容）。
