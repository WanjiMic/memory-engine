# 派生物：为什么它们不在引擎里

引擎只做四件事：**导入、检索、联想、权重**。仓库里另外还有几样东西——结构化索引、星图数据、行号锚点、冷检索库——它们不是为了检索，而是为了把「这套记忆」变得可看、可查、可校准。

本文说明它们是什么、怎么重算、以及为什么没有一并放进引擎。

---

## 1. 派生物清单

| 派生物 | 输入 | 输出 | 用途 |
|---|---|---|---|
| 结构化索引 | 账本（Markdown） | `memory.json`：天 → 段 → 时间/标签 | 给检索工具与页面读，避免每次重新解析 |
| 星图数据 | 卡片 + 权重 + 账本 | `data.js`：节点、边、日期星 | 前端可视化 |
| 记忆索引 | 账本 | 每页「时间 + 一句」的清单 | 开灯时快速定位，不读整本 |
| 情绪索引 | 账本里的标签 | 标签 → 段落清单 | 情绪温度与冷暖回捞 |
| 行号锚点 | 卡片 refs + 账本 | 锚点表：卡片 → 现行行号 | 账本插段后，卡片引用不漂 |
| 冷检索库 | 所有正本 | SQLite `chunks` + FTS5 | 检索（这一步属于引擎） |

前五样是派生物，**随时可以删掉重算**；最后一样是引擎自己建的库。

## 2. 什么时候重算

- **账本变了** → 结构化索引、记忆索引、情绪索引、星图。
- **卡片变了** → 星图、行号锚点。
- **账本中间插了一段** → 行号锚点必须重算（这是唯一会悄悄错的东西）。
- 派生物**永远不要手改**：手改的结果是下一次重算就被覆盖，而且没人知道哪份是脏的。

重算应当幂等：同样的输入，产出同样的字节（时间戳字段除外）。

## 3. 失败会是什么样

| 现象 | 原因 | 处理 |
|---|---|---|
| 星图少一截 / 半截 JSON | 写到一半被杀 | 原子写：先写 tmp 再改名 |
| 卡片点进去行不对 | 账本插段，锚点没重算 | 跑一次锚点回填 |
| 索引里有「空页」 | 日期标题下没有段落 | 正常，跳过即可 |
| 冷检索库和正本不一致 | 忘记重建 | 检索前对比正本 mtime |
| 派生物几天没变，没人发现 | 重算脚本自己失败了（路径写死、依赖缺失、被跳过），产出留在原地 | 比时间戳：产出里的 `builtAt` 早于上游正本的 mtime，就是停了 |

### 3.1 它是停了，还是没变

派生物有一种别的失败，不在上表任何一行里：它不是写坏了，是再也没写。

脚本抛异常、依赖找不到、被换机器后路径失效——这几种都不会留下坏文件，只会留下一个「还在、但旧了」的文件。页面打开照样有东西，看起来一切正常；与此同时检索库是新的，派生物是旧的，两套东西悄悄不同步。

核对三条：

1. **产出里要带时间戳**（例如 `builtAt`），并且能跟上游正本比。产出早于正本 = 停了；相等 = 是最新的。
2. **重算脚本要会叫**：退出码非 0，同时往 stderr 打一句「重算失败：<原因>」。最坏的是 `try/except` 里 `pass`——那是把失败藏起来。
3. **不写死解释器与工具路径**：写死的那一刻，换机器或升级版本就会让它静默停更；按「配置 → 环境变量 → PATH」的顺序找。

一次没发现的代价：这几天所有「看」的东西都是旧的，而「查」的东西是新的——人不会怀疑视图，只会怀疑自己的记性。


## 4. 为什么它们不进引擎

1. **契约不同。** 引擎的契约是「文本进 → 排序结果出」；派生物是「账本进 → 视图出」。混在一起，改视图就会动到检索。
2. **格式耦合。** 派生物依赖你的账本写法：`## YYYY-MM-DD` 标题、段落切分、标签怎么标。这些是「你的书」的语法，不该成为引擎的接口。
3. **可替换。** 星图、索引都是展示层，想换成别的样子随时可换；引擎不该为它们背兼容包袱。
4. **可测试。** 引擎能靠一份 demo 语料跑通全部 14 项冒烟；派生物依赖真实账本形状，很难做成通用测试。

一句话：**引擎是器官，派生物是这个人的生活习惯。** 器官能移植，习惯不能。

## 5. 想自己实现：三段伪代码

### 5.1 结构化索引

```
for each page in ledger:
    day = 从 "## YYYY-MM-DD" 取日期
    for each section in page:
        heading, time, tags, text = 解析
        emit {day, heading, time, tags, chars: len(text)}
```

### 5.2 星图

```
nodes = []
for each card in cards: nodes.append({id, day, kind, weight})
for each day in ledger:  nodes.append({id: "day:" + day, kind: "day"})
edges = 同一天的卡片连日期星
        + 共享稀有词（log(N/df) 加权）
        + 卡片 evidence 跨天命中
```

阈值建议：孤点比例 > 25% 说明分词或阈值太严；跨天边占比通常 < 10%；日期星断档 > 3 天要查日收尾是不是漏了。

### 5.3 行号锚点

```
for each card with refs like "ledger.md#L1188":
    if 该行不在卡片的日期下:
        在账本里找该卡片的日期标题，取最近的一个锚点位置
        写回 refs
```

## 6. 约定

- 派生物目录写进 `.gitignore`，不进版本库。
- 重算入口只有一个（一个命令），不要散在多个脚本里。
- 派生物里不写任何「无法从正本重建」的信息。
