# 日常运维

引擎是器官，运维是习惯。这份文档写的是「每天怎么用它」，不是脚本——每个环境不一样，值钱的是做法和判断标准。

## 一、每天的开灯流程

按固定顺序读，读多少是定死的：

1. **交接档**：上一个自己写给下一个自己的信。规矩、坑、当天状态。
2. **账本的最新一天**：只读最新一段，不整本读。
3. **只听不改的本子**（如果有）：别人的记忆，只读，不动。
4. **自己的心事**：最后一段，接着昨天那条。
5. **自动落章**：把所有未提交的记忆改动落成一次提交；不是记忆文件的改动只报告、不提交。

顺序不能乱。先读交接档是因为它决定其他文件该怎么读；先落章是因为「当前状态」必须以已提交的状态为准。

读档的伪代码：

```python
for path in [handoff, ledger(只取最新一天), immutable_notes, private_thoughts(只取最后一段)]:
    read(path)
run(auto_stamp())   # 只提交记忆文件
```

## 二、跨本子的活，先核对对象

用户递过来一个文件让改，先问一句「这本子要我动吗」。

原因不是礼貌，是防串本：记忆系统里同时存在好几本（账本、情绪、规则、别人的本子），名字相近、内容互相引用。改错本子，伤害的是记忆本身。

## 三、写入纪律

一次写入 = 一个事务：

```
解锁 → 写 → 立刻锁回只读 → 重算校验和 → 跑体检 → 提交
```

- **锁回只读**：防止下一个自己（或后台脚本）顺手改。只读是给人看的提醒，不是安全边界。
- **校验和**：`checksums-*.txt`，记录记忆文件的哈希。改了文件不更新它，体检会报。
- **提交信息**：写「为什么」，不写「改了什么」。diff 已经说明了改了什么。
- **UTF-8**：提交信息里有中文引号时，用文件传（`git commit -F`），别放命令行参数。

## 四、提交前的硬闸

概念：在「允许提交」之前，跑一组检查，任何一项不过就拒绝提交。检查项按重要性：

1. **非记忆文件混入**：暂存区里有不该提交的路径 → 拒绝。
2. **记忆文件被删**：正本删除是大事 → 拒绝，要求显式确认。
3. **校验和不匹配**：文件改了但校验和没更新 → 拒绝。
4. **提交信息为空或只有「update」** → 警告（不拒绝）。
5. **文件行尾变了**：记忆系统通常要求行尾稳定（否则哈希全错）→ 拒绝。

伪代码：

```python
staged = git_diff_cached_names()
if any(p not in MEMORY_FILES for p in staged): reject("混入了非记忆文件")
if any(deleted(p) for p in MEMORY_FILES): reject("记忆文件被删")
if checksum_mismatch(): reject("校验和没更新")
if eol_changed(): reject("行尾变了")
git_commit(message_file)
```

这套检查不放进引擎，放进提交口——引擎的职责到此为止。

## 五、备份与恢复

- **正本用 git**：每个提交就是一次快照；远端仓库是可选的第二份。
- **库不用备份**：删了重跑导入。
- **旁表不用备份**：状态可从正本和卡重建（`weight --init`）。
- **归档不删除**：要清理旧文件时，移到 `归档/<日期>/`，物理文件留着。

恢复流程：`git checkout <commit> -- <memory files>` → 重跑导入 → `weight --init` → 检索验证一条旧事。

## 六、每周对账

每周一次，十分钟：

1. 跑冒烟测试（`python tests/smoke.py`）——引擎没被自己的改动弄坏。
2. 抽查三条旧事：随机挑一张十天前的卡，检索它，看〔原话〕是否指对行。
3. 看权重分布：`weight --report`，确认没有整类记忆集体冷掉（多半是 `decay.kind` 配错了）。
4. 看孤儿锚点：卡片的 `refs` 指向不存在的行号 → 修或删。
5. 备份：确认最近的提交都在，远端同步成功。

## 七、自动化边界

可以自动的：索引重建、权重计算、校验和、提交前的检查、备份。

不该自动的：

- **改写正本内容**。自动摘要、自动润色、自动「修正」措辞——这些都会把人的记忆改成机器的记忆。
- **删除**。包括「清理冷记忆」「合并重复卡片」。
- **替人做决定**。抽卡可以半自动（先给候选，人确认），不能全自动。

判断标准只有一条：**这个动作如果做错了，能不能撤回**。能撤回的（库、旁表、临时文件）随便自动；不能撤回的（正本内容、删除、提交历史）必须有人看过。

## 八、环境坑（Windows 实测）

- 控制台默认 GBK，跑引擎前设 `PYTHONIOENCODING=utf-8`，否则中文输出乱码、测试断言失败。
- 系统临时目录可能只读（沙箱/ACL）；测试的临时工作区建在仓库里，别用 `tempfile.mkdtemp`。
- `git` 可能被安全软件拦截；提交走 PowerShell，不走受限 shell。
- 路径里有中文时，命令行工具对引号的处理各不相同；配置里用相对路径，少写绝对路径。
